启用 GitHub Copilot 代理模式后，它会自主工作——探索代码库、提出更改建议、编辑文件并运行命令。由于这些工作实时发生在你的计算机上，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以内联审查每个差异、接受或拒绝单项更改，并通过后续提示引导对话、改进或扩展工作，全程无需离开编辑器。

本练习将学习如何：

- 实时监控无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行中引导智能体，要求它添加浅色模式切换，并保留高对比度模式。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式切换。你不必从头开始新对话，可以引导现有会话扩展工作范围。

## 监控 Copilot 进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每个文件编辑都会以内联差异的形式显示在聊天中，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天记录，查看每次工具调用。你会看到文件读取、文件编辑以及需要运行的终端命令。
3. 智能体提出文件编辑时，差异会以内联方式显示：
    - 选择 **Keep** 接受更改。
    - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的所有文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后应会显示总结所做更改的最终消息。

## 引导智能体添加浅色模式

高对比度模式完成后，将在同一对话中继续添加浅色模式切换。由于继续使用相同聊天会话，智能体会保留先前工作的所有上下文，包括修改的组件、使用的样式方案和设置的 local storage 模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在请在高对比度切换旁边添加浅色模式切换。浅色模式应遵循相同的模式，通过 local storage 保存设置，并在同一 UI 区域中提供切换控件。用户应能独立启用高对比度模式和浅色模式。
    ```

2. 智能体会继续之前的工作，探索已做的更改，并提出添加浅色模式的方案。
3. 像审查高对比度模式一样，逐项检查新编辑。使用 **Keep** 或 **Undo** 处理每个差异。
4. 如果智能体的处理方向不符合预期，例如尝试以不喜欢的方式重构切换 UI，可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清提示。

> [!TIP]
> 引导进行中的会话比从头开始更快。可以通过后续提示要求调整（“简化 CSS——使用 CSS 变量，而不是重复选择器”）、纠正方向（“不要添加第三个切换控件，把浅色模式整合到现有设置面板中”）或扩展范围（“同时为两个切换控件添加键盘快捷键”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查所有更改文件。你应该会看到 Astro 组件、样式和相关测试的更新。
3. 打开几个更改文件并查看差异。确认其中体现了自定义智能体要求的无障碍模式，例如 ARIA 属性、键盘导航、语义化 HTML 和使用 local storage 保存设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课中将发布这些更改。

## 总结与后续步骤

你使用 Copilot Chat 代理模式监控并引导了正在进行的会话：逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

本课探索了以下概念：

- 实时监控智能体工作。
- 接受或拒绝单项文件编辑。
- 通过后续提示引导进行中的会话。

在[下一课][next-lesson]中，你将把无障碍功能作为拉取请求发布，并审查本实验中本地自定义智能体生成的更改。
