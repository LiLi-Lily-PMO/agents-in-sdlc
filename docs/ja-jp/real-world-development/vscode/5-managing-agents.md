GitHub Copilot のエージェントモードを使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムに確認できます。差分をインラインでレビューし、個々の変更を受け入れたり元に戻したりし、エディターを離れずに追加のプロンプトを送って作業を調整または拡張できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして受け入れます。
- 進行中のセッションに指示を与え、ハイコントラストとともにライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティ用のカスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにします。新しい会話を最初から始めずに、進行中のセッションに指示を与えて作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにインラインで表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りと編集、実行を求められたターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールの使用許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、実施した変更をまとめたメッセージが表示されます。

## エージェントにライトモードを追加させる

ハイコントラストモードができたので、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けると、エージェントはこれまでの作業、変更したコンポーネント、使用したスタイル、設定した local storage のパターンなどのコンテキストを保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは前の作業から続け、変更を調べてライトモードの追加を提案します。
3. 新しい編集を確認し、ハイコントラストモードと同じように各差分で **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえば、好みでない方法でトグル UI をリファクタリングしようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を与える方が、最初からやり直すよりも迅速です。追加のプロンプトで変更を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使用してください」)、方向を修正できます (「3 つ目のトグルは追加せず、既存の設定パネルにライトモードを組み込んでください」)、対象を広げることもできます (「両方のトグルにキーボードショートカットも追加してください」)。

## 作業対象をレビューする

コミットする前に、エージェントが変更したファイル全体を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、各ファイルの編集を確認し、変更を受け入れたり拒否したりし、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する方法
- 個々のファイル編集を受け入れたり拒否したりする方法
- 追加プロンプトで進行中のセッションに指示を与える方法

[次のレッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが生成した変更をレビューします。
