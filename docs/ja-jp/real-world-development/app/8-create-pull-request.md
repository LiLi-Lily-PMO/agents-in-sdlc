フィルター機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを作成します。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** に PR のプロセスを任せます。

> [!NOTE]
> 通常は機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。このワークショップでは手順を簡潔にするため、フィルター機能と品質に関する一連の作業を 1 つのセッションとブランチにまとめ、この PR に含めています。

このレッスンでは、次の内容を学びます。

- Agent Merge と、マージまでのプロセスを自動化する方法を確認します。
- 機能 PR 全体と検証の証拠を調べます。
- レビュー後にのみ Agent Merge を承認し、PR がマージされたことを確認します。

## シナリオ

フィルター機能のワークフローでは、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys では、開発者がマージを許可するタイミングを管理しながら、PR の残りの作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot app でプルリクエストをマージ可能にするために必要な残りの作業を自動化します。有効にすると、アプリのセッションがプルリクエストを読み込み、ブロックしている問題 (失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要に応じたリベースなど) を解決し、GitHub が許可するとマージします。バックグラウンドで実行され、アプリを再起動しても継続し、PR のマージ後に自動的に停止します。

これまでは自分で **Merge pull request** を選択してきました。Agent Merge にその作業を任せることもできます。ただし、コードの編集やマージには、引き続きユーザーの明示的な承認が必要です。マージ権限を与える前に、許可される操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したので、Agent Merge に PR のプロセスを任せます。

1. エージェントのピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンで選択しただけでは開始されません。

Agent Merge が開始され、次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- Issue からセッションを開始した場合は、関連する Issue を説明本文で参照します。
- リベースを行うか、対象ブランチとのマージ競合に対応します。
- CI を監視し、すべてのチェックが成功することを確認します。
- ほかの開発者や Copilot コードレビューからのフィードバックを監視し、コメントを解決する更新を行います。
- すべて成功した後に PR を自動的にマージすることもできます。

すべてのチェックが成功したら、Agent Merge に PR もマージさせます。

5. マージを許可する前に、PR の差分と検証の証拠を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックがあることを確認します。
8. 次のプロンプトで、エージェントにマージを明示的に依頼します。

   ```plaintext
   Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
   ```

9. 進捗を確認し、報告されたブロッカーに対応します。続行する前に PR の状態が **Merged** であることを確認します。マージ権限が有効になったことやエージェントが動作中であることだけでは、マージが完了したとはいえません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限の不足を回避しません。続行する前にブロッカーを解決してください。
